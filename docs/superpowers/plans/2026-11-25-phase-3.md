# Phase 3 RAG Implementation Plan

> Use the approved design and verify each task through the corresponding application entry point.

**Goal** · Deliver US05 PDF review and activation and US07 Vietnamese chat with verified citations.

**Architecture** · One Spring Boot backend provides private PDF storage and owns the ingestion and chat lifecycles. PostgreSQL holds validated chunks and conversation history. Next.js uses existing session-aware API calls.

**Stack** · Java 21, Spring Boot, Spring AI 1.1.1, Flyway, PostgreSQL/pgvector, Next.js and Playwright.

**Spec** · [Phase 3 design](../specs/2026-11-25-phase-3-rag-design.md)

## 1. Ingest and review PDFs

- [x] Add PDF reader tests against the Vietnam corpus, FDA fixture and a textless PDF.
- [x] Add V7–V10 migrations for documents, vector chunks, conversations, messages, citations, safe retries and trace IDs.
- [x] Build upload, review, file, activate and revoke endpoints under `/api/v1/admin/rag-documents`. Verify chunk insertion and readiness are atomic.
- [x] Document physical PDF pagination, verified corpus pages, private storage, limits and restore.

## 2. Retrieve and answer

- [x] Add adapter test using a fake HTTP provider. Verify model, dimension, structured answer and safe handling of invalid outputs.
- [x] Retrieve by cosine distance from active, compatible chunks. Verify citations against the retrieved candidates and store each complete turn transactionally.
- [x] Add ownership, history, timeout, fabricated citation, revocation and no-data cases. Exercise both chat and PDF endpoints.

## 3. Integrate screens and verify

- [x] Use the existing shell and authenticated api helper for Chatbot and Admin screens.
- [x] Exercise two accounts, document lifecycle, source links and viewport sizes with Playwright.
- [x] Run backend verification, frontend checks and browser tests. Record gaps in live model evaluation and the original-plan improvements in the [Phase 3 handoff](../../PHASE3.md).
